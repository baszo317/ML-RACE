## 0. 寫這份規則時已經知道的

- 第一部分：K1、K2、K3 都沒入選（val −0.05、−0.72、−0.03）。
- 理論（README_v16 第 9 節，和這份規則同時寫）：
  - RTS smoother 在 t 的估計是 E[θ_t | 全部資料]，用到 t 之後的觀察；在最後一個點和 filter 相同（定理 5）。
    所以「只用 D−1 以前的資料」跑 smoother，對 D 的預測和 filter 完全相同。smoother 只有兩種用法會和 filter 不一樣：
    (a) 偷看未來：D 天用的值用到 D 天或之後的資料；(b) 只在訓練窗裡做 label，測試時不需要未來的資料。
  - 兩邊平滑的 label 含有過去幾天的報酬，模型會學到假的動能（定理 6）。
- v15 B3、B4（往後 3、5 天平均的 target，取代 lgb_res）：單獨 +0.47、+0.20，合起來沒過。
- 這次任何 smoother 版本在這份資料上的成績、IC、係數，寫這份規則之前都沒有算過。

## 2. 三件事

### S1　合法的 smoother（只用到 D−1）：檢查，不另外判定

- K1、K2、K3 各抽 6 天 D（2022 起），用到 D−1 為止的資料跑 filter + RTS smoother，取 D−1 的 smoothed 值往前預測一天。
- 要和第一部分 filter 的 D | D−1 相同（差 < 1e−12）。相同就代表 S1 的 AR 和 K1、K2、K3 完全一樣。

### S2　偷看版（不能上線，只報告）

目的：說明論文裡的 smoother 為什麼看起來有效。用全部資料跑 RTS smoother（K1 用到價格的最後一天 2026-11-02，K2、K3 用到 2026-10-22），兩種用法：

- 「D 的 smoothed 值」θ_{D|T}；
- 「D−1 的 smoothed 值」θ_{D−1|T}（論文常見的「先把整段平滑，再用前一天的平滑值」）。兩種都用到 D 天或之後的資料。

| 代號 | 參數 | 放法 |
|---|---|---|
| S2-K1 | 每個 fold 第一部分選到的 (φ, q) | 對沖改用 smoothed beta（截斷、補值同 K1）；v11 和 W0 |
| S2-K2 | 每個 fold 選到的 (q_a, q_b)；另外固定 (1e−3, 0)、(0, 1e−3)、(0, 1e−2)、(1e−3, 1e−2) | 第一部分的大盤項公式，(â, b̂) 換成 smoothed 值，參考值 (â⁰, b̂⁰) 換成 q = (0, 0) 的 smoothed 值；v11 |
| S2-K3 | 每個 fold 選到的 q；另外固定半衰期 5、20、60 天 | smoothed μ ≥ 0 用 v11，否則 W0 |

### S3　合法的用法：smoother 只做訓練的 label（判定）

- 模型：線性回歸（OLS + 截距），B 組 67 個 feature；訓練窗 2020-03-02 到 fold 開始前一天，用到的 label 都在訓練窗裡。
  前處理：用訓練窗的 1%、99% 分位數截尾，再用訓練窗的平均、標準差標準化，缺值補 0。不加權。
- label（e = clip(resid_r, ±5%)，resid_r = 個股盤中報酬 − 當天 100 支的平均）：
  - **S3-0（對照）**：e_t。
  - **S3a**：每支股票的 e 在訓練窗裡跑 local level 的 RTS smoother（q 固定，對應 filter 的半衰期 5 天：K = 1 − 0.5^{1/5}，q = K²/(1 − K)；起始 μ ~ N(0, 10⁴·Var(ε))），label = smoothed 值。
    只用訓練窗的資料，所以窗尾的 label 只看到窗尾。
  - **S3b**：同 S3a，半衰期 20 天。
  - 只報告 **S3f**：只往後看的指數平均 f_t = K e_t + (1 − K) f_{t+1}（半衰期 5 天，訓練窗最後一天 f = e），相當於 v15 B3、B4 的「多天 target」。
- 放法：預測縮放成 lgb_res 的當天平均和標準差，放進 v11 的 LightGBM 部分，(lgb_res + X1 + 候選) / 3（和 SVM、RF 相同）。
- **比較：(v11 + S3x) − (v11 + S3-0)**。差異只來自 label。

## 3. 判定（只有 S3）

1. S3a、S3b 各自：val > 0 → 入選。
2. 入選的預測平均後放進去：(v11 + 入選) − (v11 + S3-0)，**hold > 0 而且 post > 0 → 通過**。另外報告和 v11 本身比。
3. 通過也只是研究結果；要不要改每天的程式由使用者在 11/23 前決定。

# v11 第二部分：大盤觀點（timing）和選股觀點（xsec）的改進（2026-10-26 16:10 寫，任何候選的成績算出來之前）

使用者的要求：「大盤觀點：和大盤盤中報酬的相關 +0.1 → 約 +2 bp/日；選股觀點：family 的 IC +10% → +0.3–0.5 bp/日。
用這些改進弄成 V11，只要 bp 是正的都可以考慮修改。」
第一部分（Alpha158 重挑，`PREREG_v11.md`）的結論是不加群組；這一部分以 v9 為底，只改決策方式和加成員。
v9 的檔案都不改；程式在 `v11\research\v11b_*.py`，結果在 `v11\results\v11b_*.txt`。

## 1. 候選（7 個，每個單獨加在 v9 上）

大盤觀點（目標：提高淨曝險和大盤盤中報酬 m 的相關）：

- **T1 pbar50**：pbar 改成只用 Top50 的 p_raw 平均（v9 用 100 支）。m 是 Top50 的平均，兩者對齊。不重訓。
- **T2 夜盤反轉**：pbar' = pbar − 0.5 × sd(pbar) × clip(z_night, −3, 3)。z_night = night_ret ÷ 前 250 個交易日 night_ret 的
  標準差（只用過去，至少 60 天）；sd(pbar) = 前 250 個交易日 pbar 的標準差（只用過去，至少 20 天；不足時這一項 = 0）。
  夜盤缺值時這一項 = 0。依據：v8 4.2，夜盤和 m 的相關在 val、hold、post 都是負的（隔夜漲、盤中回吐），但 pbar 幾乎沒用到它。
  0.5 是事先定的（「比 pbar 弱的訊號給一半的權重」），不在 val 上調。
- **T3 月初**：每個月前 3 個交易日，在對沖之前把分數整體往上移，讓 Top50 裡（除權息規則以外的股票）多 5 支猜 1
  （淨曝險 +0.2）。依據：v8 第七節，月初 3 天的大盤盤中報酬在四段都偏正（turn-of-the-month）。日曆事先公告，live 做得到。

選股觀點（目標：提高 p_e 的 IC）：

- **X1 第二個 LightGBM**：新增選股成員 lgb_res_xrN，LightGBM、參數和 lgb_res 相同，feature 用 mlp_res_xrN9 那組（B9 + XR + NEW +
  XRN + SIG，106 個）。p_e = (4 個 MLP 平均 + 兩個 LightGBM 平均) / 2。seed 1–5、6 個 fold（30 個模型）。
  依據：v9 裡最大的改進是加入 LightGBM（拿掉後 hold 從 14.33 掉到 12.12），成員多樣性比 feature 有用。
- **X2 回歸型 LightGBM**：新增選股成員 lgb_res_soft，objective = cross_entropy，label = 0.5 + clip(resid_r, −5%, 5%) / 10%
  （把報酬大小放進 label，不用權重），B 67 個 feature。它的輸出尺度和二元模型不同，所以每天先減去當天平均，再縮放到和
  lgb_res 當天的標準差相同，然後和 lgb_res 平均。seed 1–5、6 個 fold。
- **X3 z-score 合成**：每個選股成員（4 個 MLP、LightGBM）先各自減去當天平均、除以當天標準差，再照 v9 的權重合成，
  最後縮放回 v9 當天 p_e_c 的標準差（只改排序，不改和大盤觀點的相對尺度）。不重訓。
- **X4 跨天平滑**：p̃_t = 0.5 × p_e_c,t + 0.5 × p̃_{t−1}（同一支股票；前一天缺值就用當天），縮放回 v9 當天 p_e_c 的標準差。
  不重訓。0.5 事先定，不調。

都不動：w_T 0.5、除權息 4 天猜 0、對沖 λ 0.75、其他成員。不重新調 v9 已經定好的係數（w_T、λ、權重），因為 v9 第十一節顯示
在同一份資料上重調只是在追雜訊。

## 2. 怎麼比

- v9 的 walk-forward 預測（`v9\cache\wf9_preds.csv.gz`、`v8\cache\`，重算 val 13.99 / hold 14.33 / post 16.59）當 baseline；
  每個候選只改它那一項，和 v9 算每日成對差（Top50 bp/日，v9 的規則），t 用 Newey–West（5 lags）。
- 期間同 v9：val 2022–2024、hold 2025-01 到 2026-05、post 2026-06-01 到 2026-10-22。
- 報告（不參與決定）：corr(pbar 或 pbar', m)、corr(淨曝險, m)、timing、xsec、p_e 的 rank IC（100 支、Top50）、每日 sd、P(19 天 > 0)。

## 3. 規則（使用者的規則）

1. **入選：val 的 AR 差 > 0**（「只要 bp 是正的」），7 個各自判斷。
2. **v11 = v9 + 所有入選的改法一起**。X3、X4 都入選時兩個一起做（先 z-score 合成，再平滑）；T1、T2 都入選時，T2 用 pbar50。
   X1、X2 都入選時 LightGBM 部分 = (lgb_res + lgb_res_xrN + 縮放後的 lgb_res_soft) / 3。
3. **檢驗（和 v9 相同）**：v11 對 v9 的 **hold 差 > 0 且 post 差 > 0** → v11 成立，做每天的預測程式（和 v9 並行輸出，
   上傳哪一個由使用者決定）；任一段 ≤ 0 → v11 不成立，live 維持 v9。
4. 只報告：val（挑選用，偏高）、全期、static 期間（6/1–9/30）、10 月、拿掉每一項的 ablation（不拿來改組合）。

## 4. 誠實說明

- 7 個候選裡，沒有效果的改法 val > 0 的機率約一半，所以入選名單一定混了雜訊；hold、post 的檢驗是唯一的保護，
  而一次檢定也只有約一半的機率擋下沒用的組合。這和 v9、v10 的規則一樣寬。
- hold、post 在之前的版本都看過；T2、T3 的依據（v8 第 4.2 節、第七節）本身就看過 hold、post 的方向，所以這兩項的 hold、post
  不算乾淨的檢驗。乾淨的只有 10/27 以後的 live，而以這種幅度，live 看不出差別。
